# Omoi for Us v3

Family／Friendsを、身近な人の選択を予想するゲーム「Omoi for Us」に統合します。

## 確定した仕様

- 2〜6人、スマホ1台。予想は口頭・指で一斉に出し、端末では主役の回答と的中者を選びます。
- 家族用166問・友人用150問。深さは分けず、選んだ種類の全問から抽選します。
- 一人の主役につき通常と条件変更後の2回。主役以外の的中者に各1点。全員1回ずつ主役になると終了します。
- パスは同じ主役で引き直し、その問いの得点をまとめて取り消します。途中終了も未完了の問いの得点を除き、順位を付けません。
- 進行はsessionStorageに保存し、同じタブで再開できます。完了した問いの回答選択は保持せず、得点の根拠となる的中者だけを保存します。
- Usは未公開・レビュー待ちの開発プレビューです。localhost / 127.0.0.1 / ::1で確認できます。本番ホストでは公開準備中画面を表示します。

## 316問の改稿と原文

元の`shared/questions/family.json`（166問）と`friends.json`（150問）、深掘り、表示文は変更していません。保存時点は`f0042facf16bc8f792a19fa912b3b5fe17618346`、保存用タグは`archive/family-friends-before-us-v3`です。タグは共通コードを含む移行前リポジトリ全体を指します。

個別の編集内容は`tools/us-edits/family.psv`と`friends.psv`にあります。一行の形式は「元の配列での1始まりの番号 | 問い | 選択肢1 | 選択肢2 | 選択肢3 | 追加条件」です。汎用テンプレートから選択肢や条件を自動補完しません。思い出に関する元の問いは、その思い出をどう話す・残す・振り返るかを選ぶ場面として改稿しています。

番号対応は`source-contract.json`のコミットと元ファイル全体のSHA-256に固定しています。並びや元データが変わると生成を停止します。生成JSONの各問には元の質問ID・本文ハッシュ・カテゴリ・Levelも記録し、1対1の対応を検証します。生成元はCodexによる改稿として記録し、旧データの生成元や承認を転用しません。改行は改稿表に明記した`\n`だけを採用し、表示時の自動文節分割は行いません。

```sh
node tools/build-us-dataset.mjs
node tools/build-us-dataset.mjs --check
node tools/verify-us-dataset.mjs
```

現行の編集記録は全問がレビュー待ちです。再生成しても公開・承認は行いません。公開準備を行う際は、編集記録・承認記録・データ・マニフェストの整合を確認する変更を別途用意してください。

## 実装

`us/game-engine.mjs`は画面から独立した状態遷移を担当します。的中者を集合として扱い、得点は終了済みの主役の記録から計算します。現在の問いの加点記録は独立しているので、パス時に以前の主役の点まで失わずに取り消せます。

保存状態にはバージョンとデッキ内容の識別値を付けます。再開時は問い・選択肢、主役の順番、人数、得点記録との対応を検証します。データ改訂や破損で対応しない保存状態からは新規開始を案内します。保存が使えない環境ではメモリ上で遊べます。

旧URLから別の種類を開いた時は、その種類を選択した開始画面を表示し、以前のゲームは開始操作まで上書きしません。前のゲームへ戻るボタンも用意しています。参加者名は16文字以内で、同じ名前は区別できる名前に変更してもらいます。

`us/deck.mjs`はデータ構造と公開判定を担当します。未承認のゲームは明示的なローカル開発プレビューだけで表示し、本番では未公開データのゲームを開始させません。

Family／Friendsは公開マニフェストで`archived`、置き換え先は`us`です。旧URLはゲーム用スクリプトを読み込まず、対応する種類が選択された`/us/?deck=family`または`/us/?deck=friends`への案内を表示します。

## 見た目

承認された3画面の画像を基準に、白地、青の操作・選択状態、オレンジの条件変更、UD書体を使います。デザイン画像の人名は入力例で、実際の初期表示は「プレイヤー1〜4」です。人数の追加・削除、答えの選び直し、終了確認、エラーや再開案内は、ゲームに必要な状態として同じ見た目で追加しています。3画面を同時表示するアプリではありません。

このカードゲームにはキャラクターや背景絵の操作がないため、ゲーム素材・スプライトは不要です。文面、番号、選択状態、得点はすべてHTMLとCSSで表示します。

外部フォント配信が使えない環境でもUD書体で表示できるよう、BIZ UDPGothic由来のサブセットWOFF2をSIL OFLとともに同梱しています。フォントの由来・照合値・再生成方法は`us/fonts/README.md`を参照してください。

機能上必要な補足として、主役の答えを押すと選び直せるようにし、得点画面の追加条件は必要な時に開ける表示にしています。条件変更の見出し色は、白い大きな太字とのコントラストが3:1を超える`#e66a38`へ調整しています。枠と条件の強調色は明るいオレンジを維持しています。

## 実装時の確認記録

採用した[3画面のデザイン案](design/omoi-for-us-v3-concept.png)と、実ブラウザの[開始画面](screenshots/us-v3-setup.png)・[条件変更](screenshots/us-v3-condition.png)・[得点記録](screenshots/us-v3-score.png)を見比べて確認しています。実画面は、実際の316問から家族用005を引き、操作して到達した状態です。

| 比較した点 | 確認・調整した内容 |
|---|---|
| 文面と構成 | ブランド・見出し・選択肢・条件変更・的中者の表示を対応。画像のサンプル名は入力名に置き換わります。 |
| 配置 | 一つの問いに集中する縦の構成を維持。条件変更後も元の問いと選択肢を表示します。 |
| 書体と大きさ | UD書体を同梱し、見出し・本文・番号・操作ボタン・名前を個別に設定。自動文字縮小は使いません。 |
| 配色 | 白地、青い操作と選択状態、オレンジの条件変更を維持。条件見出しだけはコントラスト確保のため調整しています。 |
| 選択状態 | 的中者のチェック、青い枠、+1が連動。答えの修正は回答欄から行えます。 |
| 画面幅と動き | 320・390・768・1280pxで横はみ出しを検証。参照用の512×1024pxでも撮影。キーボードと動きを減らす設定を確認しています。 |

ブラウザ機能はBrowserプラグインが提供されていないため、PlaywrightとChromiumを使っています。Nodeの単体テスト74件、ブラウザの21ケース、データ契約・原文照合・再生成の検証が成功しています。Couples、Adultsの開始前案内、Self-Careの既存フローも含みます。Us自体の読み込みには外部フォント配信へのリクエストやコンソールエラーがありません。

ゲームが実際の会話でどう受け取られるかと、改稿した全質問の公開承認は、利用者との試用・内容レビューで扱う項目です。
