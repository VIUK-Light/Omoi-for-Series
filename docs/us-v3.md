# Omoi for Us v3

Family／Friendsを、身近な人の選択を予想するゲーム「Omoi for Us」に統合します。

## 確定した仕様

- 2〜6人、スマホ1台。予想は口頭・指で一斉に出し、端末では主役の回答と的中者を選びます。
- 家族用166問・友人用150問。深さは分けず、選んだ種類の全問から抽選します。
- 一人の主役につき通常と条件変更後の2回。主役以外の的中者に各1点。全員1回ずつ主役になると終了します。
- パスは同じ主役で引き直し、その問いの得点をまとめて取り消します。途中終了も未完了の問いの得点を除き、順位を付けません。
- 進行はsessionStorageに保存し、同じタブで再開できます。完了した問いの回答選択は保持せず、得点の根拠となる的中者と、答えが変わったかだけを保存します。
- Usは未公開・レビュー待ちの開発プレビューです。localhost / 127.0.0.1 / ::1で確認できます。本番ホストでは公開準備中画面を表示します。

## 316問の改稿と原文

元の`shared/questions/family.json`（166問）と`friends.json`（150問）、深掘り、表示文は変更していません。保存時点は`f0042facf16bc8f792a19fa912b3b5fe17618346`、保存用タグは`archive/family-friends-before-us-v3`です。タグは共通コードを含む移行前リポジトリ全体を指します。

個別の編集内容は`tools/us-edits/family.psv`と`friends.psv`にあります。一行の形式は「元の配列での1始まりの番号 | 問い | 選択肢1 | 選択肢2 | 選択肢3 | 追加条件」です。汎用テンプレートから選択肢や条件を自動補完しません。思い出に関する元の問いは、その思い出をどう話す・残す・振り返るかを選ぶ場面として改稿しています。

番号対応は`source-contract.json`のコミットと元ファイル全体のSHA-256に固定しています。並びや元データが変わると生成を停止します。生成JSONの各問には元の質問ID・本文ハッシュ・カテゴリ・Levelも記録し、1対1の対応を検証します。生成元はCodexによる改稿として記録し、旧データの生成元や承認を転用しません。改行は改稿表に明記した`\n`だけを採用し、表示時の自動文節分割は行いません。

```sh
node tools/build-us-dataset.mjs
node tools/build-us-dataset.mjs --check
node tools/verify-us-dataset.mjs
```

現行の編集記録は全問がレビュー待ちです。再生成しても公開・承認は行いません。公開準備を行う際は、編集記録・承認記録・データ・マニフェストの整合を確認する変更を別途用意してください。

## 実装

`us/game-engine.mjs`は画面から独立した状態遷移を担当します。的中者を集合として扱い、得点は終了済みの主役の記録から計算します。現在の問いの加点記録は独立しているので、パス時に以前の主役の点まで失わずに取り消せます。最初の回答はその問いの間だけ保持し、条件変更後の回答と比較します。完了後は回答の番号を消し、変化の有無だけを残します。

保存状態にはバージョンとデッキ内容の識別値を付けます。再開時は問い・選択肢、主役の順番、人数、得点記録との対応を検証します。データ改訂や破損で対応しない保存状態からは新規開始を案内します。保存が使えない環境ではメモリ上で遊べます。

旧URLから別の種類を開いた時は、その種類を選択した開始画面を表示し、以前のゲームは開始操作まで上書きしません。前のゲームへ戻るボタンも用意しています。参加者名は16文字以内で、同じ名前は区別できる名前に変更してもらいます。

`us/deck.mjs`はデータ構造と公開判定を担当します。未承認のゲームは明示的なローカル開発プレビューだけで表示し、本番では未公開データのゲームを開始させません。

Family／Friendsは公開マニフェストで`archived`、置き換え先は`us`です。旧URLはゲーム用スクリプトを読み込まず、対応する種類が選択された`/us/?deck=family`または`/us/?deck=friends`への案内を表示します。

## カードUI

既存Omoi forのカード型UIをv3でも使用します。`shared/question-card.mjs`の共通フレームと表裏の切り替え、`shared/styles.css`のカード形状・影・3D回転を共有します。既存シリーズの本文フォーマッタはそのままです。

- カード幅は最大340px、短い問いは縦横比63:88。長い文や6人分の得点入力では、両面の内容に合わせて自然に高さが伸びます。文字の自動縮小やカード内部のスクロールは使いません。
- 通常の問いと3択を表面、追加条件・元の問い・同じ3択を裏面へ表示します。条件変更で同じカードのDOMを保持して裏返します。
- 表示していない面は`aria-hidden`と`inert`で読み上げ・操作から外し、選択肢のボタンは表示中の面だけに用意します。動きを減らす設定では回転と配布のアニメーションを停止します。
- ヘッダー、文字、入力欄、ボタン、余白は既存シリーズのサイズ感に合わせています。Usの青はブランド・選択状態・得点の強調に使用します。
- `us/card-view.mjs`はUsの問い・3択・答え・的中者を共通フレームに渡します。ゲームの得点計算や保存形式は変更していません。

UD書体は引き続き同梱し、外部フォント配信なしで表示します。由来・照合値・再生成方法は`us/fonts/README.md`に記録しています。

`docs/design/omoi-for-us-v3-concept.png`と`docs/screenshots/`に残した画像は初期案の記録です。現在の見た目の基準は既存Omoi forの実装です。初期案の大きな文字・青いボタン・別枠の条件表示から、共通カードを使う構成へ変更しています。

## 確認する流れ

開始 → 通常の問いで答えを直接選択 → 的中者 → 裏面の追加条件と最初の答え → 前後の答えと的中者 → 次の主役 → 得点と今日の発見。パス・修正・途中再開も同じ状態遷移で扱います。

共有カードの変更時は、Usに加えてCouples・Adults・Self-Careのカード表示を確認します。モバイルでは320pxと390px、広い画面では768pxと1280pxを確認し、長文を含む316問の両面で文字の欠けや横へのはみ出しがないことを検証します。

## 操作と読みやすさの改善

参加者の追加では、空欄の既定名も考慮して未使用の名前を選びます。途中の参加者を削除して追加しても、既定名が重複しません。

予想がそろったら選択肢を直接タップします。「答え画面へ」の一段階をなくし、的中者をまとめて選ぶ「全員的中」を用意しています。6人全員が的中する1周は、設定やパスを除き96タップから36タップになります。全員外れの場合は36から24タップです。

回答形式はバージョン2です。保存先のキーを保ち、旧形式や改訂前の質問による途中データは更新案内とともに新規開始へ戻します。比較に必要な回答がない状態を、そのまま再開させません。

「今日の発見」には完了した主役ごとの問いと、条件で答えが変わったかを表示します。回答の番号・本文は履歴に保存しません。途中終了では完了していない問いを振り返りに含めません。

通常表示の選択肢は16px、元の問いは14pxに改善しています。「大きく表示」ではカード幅を最大480px、選択肢を20pxにして自然に高さを伸ばします。表示設定は同じタブで保持します。

家族用13問・友人用20問は、最初の行動や優先することが明確になるよう個別に修正しています。問数は家族166・友人150のままで、公開のレビュー待ち状態を保っています。
